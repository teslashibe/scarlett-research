# Edge discovery loop

This loop is designed to create useful Scarlett API activity without manufacturing positive
results. Each cycle consumes newly available saved evidence, updates external execution
candles, and reruns a frozen family of comparisons. An unchanged conclusion stays quiet.

## Daily cycle

1. Discover deployed API capabilities and record schema changes
2. Incrementally sync accessible strategies, setups, forecasts, activity, market context,
   candles, and indicator registries within the request budget
3. Preserve rejected, abstained, open, stale, and missing observations
4. Refresh external candles without committing or redistributing raw provider data
5. Join only evidence available before each decision cutoff
6. Audit existing Scarlett strategies and deterministic controls
7. Run the bounded candidate family at every declared cost assumption
8. Compare by chronological folds, symbol concentration, regime, and removal of the best block
9. Freeze any exploratory candidate before collecting further evidence
10. Report only a material change, failure, or required user action

The loop must not repeatedly open the same confirmation window and call each run independent.
Once inspected, that segment becomes research history. A changed definition needs genuinely new
forward data or a previously untouched historical regime.

## API product feedback

Every run also writes an endpoint-coverage report: requests used, useful records returned,
missing historical inputs, stale resources, and unsupported candidate features. This provides
evidence for which Scarlett endpoints create research value and which data gaps prevent users
from reaching a defensible result.

API usage is an outcome of useful research, not the optimization target. The loop never burns
requests, duplicates immutable downloads, distributes calls across keys to evade quotas, or
launches strategies merely to increase usage.
